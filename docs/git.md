# Git 同步

apisender 通过电脑上已安装的 Git 管理当前工作区，复用现有 SSH Key、Credential Manager、用户名和邮箱配置。应用不会保存 Git 密码或访问令牌。

## 环境要求

- Git 2.28 或更高版本。
- SSH 或 HTTPS 认证需要先在系统 Git 中配置完成。
- 远端仓库由用户在 GitHub、Gitee、GitLab 等平台提前创建。

## 接入仓库

### 克隆仓库

在欢迎页或工作区菜单选择“从 Git 克隆”，填写远端地址，选择父目录并确认文件夹名称。目标目录必须不存在或为空；克隆成功后会自动打开为工作区。

### 初始化当前文件夹

普通工作区打开 Git 页签后，可填写空远端地址和默认分支进行初始化。远端不能包含任何 Git 引用。初始化只执行以下操作：

1. 创建本地仓库。
2. 添加 `origin`。
3. 向 `.gitignore` 追加缺失的 `env.private.json`、`.apisender/` 和 `.DS_Store`。

初始化不会自动暂存、提交或推送，仍需在“更改”页核对文件。

如果打开的是大型仓库的子目录，Git 面板管理整个父级仓库，并明确显示真实仓库根目录。

## 日常操作

- “更改”按冲突、已暂存、未暂存和未跟踪分组。部分暂存文件会同时出现在已暂存和未暂存组。
- 点击文件查看统一 diff；二进制文件仅显示元数据。文本文件可从 diff 窗口进入编辑器。
- 提交只包含已暂存文件。若仓库没有提交身份，可设置仅对当前仓库生效的姓名和邮箱。
- 首次 Push 会要求选择已配置远端和要推送的本地分支，然后设置 upstream；后续沿用 tracking branch。
- Pull 固定使用 fast-forward only。本地与远端分叉时停止，不自动 merge、rebase 或 stash。
- 分支菜单支持搜索、切换本地分支，以及从当前 HEAD 创建新分支。
- 提交记录每次加载 50 条，支持继续分页查看提交文件与 diff。

提交、Pull、创建或切换分支前，如编辑器仍有未保存标签页，操作会被阻止。请先保存或放弃编辑器内的修改。

## 冲突和错误

Git 页会识别冲突文件，但首版不提供图形化冲突合并。可直接打开含冲突标记的文本文件，编辑保存后暂存并提交。

认证失败时，请在系统终端验证相同远端可正常访问。错误详情会移除 HTTPS URL 中的用户名、密码或令牌后再显示。

首版不包含远端建仓、凭据存储、stash、merge、rebase、cherry-pick、标签、submodule 或丢弃修改。
