# Git 页面刷新循环修复设计

## 背景与目标

Git 页面读取状态时会执行 `git status`。系统 Git 默认可能为刷新索引创建并删除 `.git/index.lock`，文件监听器把这类内部变化发送为 `git-changed`，前端随后再次刷新 Git 状态，形成“读取状态 → Git 管理目录变化 → 再次读取状态”的循环。刷新按钮根据 `loading` 状态显示旋转动画，因此表现为持续闪烁。

本次修复的目标是阻止只读 Git 操作产生可选锁，同时保留真实工作区文件变化和外部 Git 操作触发的自动刷新。

## 方案

后端 Git 服务把命令分为两类：

- 只读命令：设置 `GIT_OPTIONAL_LOCKS=0` 后启动系统 Git。状态、分支、提交、diff、身份读取和仓库探测等查询使用该路径。
- 写入命令：保持 Git 默认锁行为。暂存、提交、推拉、分支切换、初始化、连接远端和克隆继续使用正常命令路径。

文件监听器和前端 `git-changed` 防抖逻辑保持不变。这样真实的 `.git/HEAD`、index、refs 或工作区文件变化仍会刷新 Git 页面，而页面自己的查询不会再次触发监听。

## 数据流

1. 工作区或 Git 管理目录发生真实变化。
2. Rust 文件监听器发送 `git-changed`。
3. 前端防抖后调用 Git store 的完整刷新。
4. 后端通过禁用 optional locks 的只读命令读取状态。
5. 查询不写入 `.git`，监听器不会因本次刷新再次发出事件。
6. Git store 结束 `loading`，刷新图标停止旋转。

## 错误与兼容性

- 不过滤全部 `.git` 事件，避免遗漏用户在终端或其他工具执行的提交、切分支和暂存操作。
- 不改变写命令的锁策略，继续依赖 Git 原生互斥与完整性保护。
- Git 2.28 及以上支持 `GIT_OPTIONAL_LOCKS`；Windows、macOS 和 Linux 使用同一环境变量。
- 现有结构化错误、输出大小限制和凭据脱敏行为不变。

## 测试与验收

- 新增 Rust 临时仓库集成测试：调用状态读取前后，`.git` 目录修改时间保持不变。
- 测试先在旧实现上失败，再在只读命令禁用 optional locks 后通过。
- 重新执行 `cargo test --test git`、完整 `cargo test`、前端 Git 测试、TypeScript 检查、生产构建和 `git diff --check`。
- 不默认启动桌面应用做 UI 冒烟测试；本地自动化验证不会宣称真实桌面交互已经回放。

## 非目标

- 不关闭 Git 文件监听。
- 不隐藏或取消刷新按钮的加载动画。
- 不通过延长防抖时间掩盖后台循环。
- 不改动 Git 页面其他交互与布局。
